- (decision) Entwurf-Widersprüche nach Forge entschieden: kein NATS, keine FlatBuffers, 99,5 % statt 99,9 %, 10 statt 50 gleichzeitige Uploads, /storage/uploads statt /storage/temp, Slideshow/PWA/pHash/RAW nach V1.x
- (requirement) R1 (forge §Nutzer; draft §10, §13): Admin legt Konten an, weist Rollen und Gruppen zu und setzt Status aktiv/deaktiviert/gesperrt; ohne vom Admin angelegtes aktives Konto ist keine Anmeldung möglich (keine offene Registrierung)
- (requirement) R2 (forge §Scope V1; draft §11): Anmeldung passwortlos per WebAuthn/FIDO2 (Passkey, Windows Hello, YubiKey, Platform Authenticator), TOTP nach RFC 6238 als Fallback
- (requirement) R3 (forge §Nutzer; draft §12): Rollen vergeben RBAC-Berechtigungen (u. a. image.*, user.*, album.publish, system.admin; Standardrollen Viewer/Editor/Admin); Aktion ohne Berechtigung wird abgewiesen; Rollen beeinflussen nie die Sichtbarkeit
- (requirement) R4 (forge §Nutzer): Sichtbarkeit pro Album/Bild public / alle angemeldeten (Default) / Gruppen / privat (nur Owner); Bild erbt vom Album, restriktivste gewinnt, gilt in Raster, Karte, Suche, API
- (requirement) R5 (forge §Nutzer): Veröffentlichen = Album auf public (album.publish); Bilder darin ohne Konto sicht- und auffindbar, einzeln pro Album ausschließbar; Einzelbild nie ohne public-Album, Gruppen-/private Bilder nie öffentlich
- (requirement) R6 (forge §Metadaten, §Verworfen): Ausgeliefert werden nur Ableitungen (AVIF, Thumbnails), nie Originale; Ableitungen bis auf Copyright metadatenfrei; eine Ableitung pro Bild für intern und öffentlich
- (requirement) R7 (forge §Metadaten): öffentliche Metadaten nur aus Admin-Positivliste, überschreibbar pro Album und Bild; mehrere public-Alben = Schnittmenge
- (requirement) R8 (forge §Metadaten): öffentliches GPS pro Album exakt/vergröbert/aus; mehrere Alben: aus > vergröbert > exakt
- (requirement) R9 (forge §Upload; draft §3.1): Admin per SCP/SFTP, alle anderen per Web (Einzel, Mehrfach, Drag & Drop) mit eigenem Pfad nach /storage/uploads/<username>/<Pfad>; Verarbeitung startet automatisch
- (requirement) R10 (forge §Upload): Import verschiebt nach /storage/originals/<gelieferte Struktur>/<yyyy-mm-dd_hhmmss>.<ext> aus Aufnahmezeit (Fallback Datei-Zeitstempel), Kollision -> atomarer Zähler; Konvention Kontinent/Land/Provinz/Region/Stadt[/yyyy/mm] vorgeschlagen, nicht erzwungen; keine Sortierung nach GPS
- (requirement) R11 (forge §Upload, §Metadaten): Original und physischer Pfad nach Import unveränderlich, SHA256 bleibt gültig; Verschieben/Umbenennen nur in der DB
- (requirement) R12 (forge §Upload; draft §8): SHA256-Duplikat wird geparkt und Admin/Owner in der Weboberfläche angezeigt
- (requirement) R13 (forge §Architektur, §Scope; draft §3.2, §3.3): Pipeline für JPEG/PNG/TIFF/HEIC/AVIF/WebP: Hash, Metadaten, Geo-Validierung, AVIF, Vorschaubilder, DB; jeder Job mit sichtbarem Status, Retry, Fehlerzustand
- (requirement) R14 (forge §Metadaten; draft §4, §9): alle EXIF/IPTC/XMP-Metadaten beim Import in die DB, Anzeige aus der DB; angemeldete sehen sie vollständig in der Detailansicht
- (requirement) R15 (forge §Metadaten; draft §13): Metadaten-Edit nur in der DB, Originalwert daneben erhalten und einsehbar, Anzeige bevorzugt bearbeitet
- (requirement) R16 (forge §Metadaten): Bewertung 0-5 einmal pro Bild, freie globale Tags, Autor aus EXIF/IPTC getrennt vom Owner (Uploader)
- (requirement) R17 (forge §Ortsmodell; draft §5): GPS -> Reverse-Geocoding Kontinent/Land/Provinz/Region/Stadt ist Wahrheit für Karte, Geo-Navigation, Geo-Filter
- (requirement) R18 (forge §Ortsmodell): ohne GPS Ort aus Ordnerpfad als ungefähr markiert, sonst Ort fehlt; Ordner != GPS -> Prüfliste
- (requirement) R19 (forge §Ortsmodell, §Scope): Navigation nach Ort (Kontinent..Stadt) und nach Ordnerbaum
- (requirement) R20 (forge §Performance; draft §5): Karte mit serverseitigem Clustering, Kartensuche Radius/Polygon/Bounding Box
- (requirement) R21 (draft §9): Raster responsive mit Lazy Loading und Infinite Scroll; Detail mit Bild, Metadaten, Karte, Tags, Bewertung
- (requirement) R22 (draft §7): Volltext über Titel, Beschreibung, Keywords, Kamera, Objektiv; Filter Land, Region, Stadt, Kamera, Objektiv, Jahr, Monat, Autor, Bewertung, Tags, per UND kombinierbar
- (requirement) R23 (forge §Scope; draft §13, §19): Admin-Monitoring Worker, Job-Queue, DB, Speicher, Duplikate, Prüfliste; Reindexing anstoßen; Metriken Uploads/s, Jobs, Queue-Länge, API-Zeiten, DB-Latenz
- (requirement) R24 (forge §Architektur): Backup/Restore Originale RPO 0, DB PITR, dokumentierter getesteter Restore, RTO <= 24 h; Ableitungen regenerierbar
- (requirement) R25 (forge §Architektur): öffentliche Galerie zeigt bei Ausfall/Wartung statische Wartungsseite
- (requirement) R26 (draft §13): Bilder löschen mit Berechtigung image.delete; Semantik offen
- (constraint) Stack: Linux, C++ Drogon (REST/JSON, Sessions, RBAC), PostgreSQL 19 + PostGIS GEOGRAPHY(Point,4326), Angular 22, H2O (TLS, HTTP/2, HTTP/3, Reverse Proxy), libvips + libavif (forge Einleitung; draft §2, Stack)
- (constraint) ein Host, systemd-Units; synchron gRPC über UDS (Protobuf) + Socket Activation + gRPC Health; asynchron Job-Queue in PostgreSQL; kein NATS, keine FlatBuffers (forge §Architektur, §Verworfen)
- (constraint) Leistungsziele bei 1 Mio. Bildern auf Zielhost, auch während Import: Karte <300 ms, Raster nächste Seite <150 ms p95, Suche/Filter <200 ms p95, API-Metadaten <100 ms p95; Thumbnails statisch vom Edge (forge §Performance)
- (constraint) Import >= 10.000 Bilder/h JPEG/HEIC, Worker niedrig priorisiert; 10 gleichzeitige Uploads; Bestand ~200.000, Ziel 1 Mio. (forge §Performance; draft §17)
- (constraint) 99,5 % Verfügbarkeit ohne Wartungsfenster; Datensicherheit vor HA (forge §Architektur)
- (constraint) Sicherheit: TLS 1.3, CSP, XSS-/CSRF-Schutz, Rate Limiting, Audit Logging; Session-Cookies Secure, HttpOnly, SameSite Strict (draft §11, §17)
- (constraint) Betrieb: strukturierte JSON-Logs, Metrik-Export per OpenTelemetry (draft §18, §19)
- (constraint) Originale nie verändert, kein Rückschreiben von Metadaten in Dateien (forge §Metadaten, §Verworfen)
- (assumption) privat gilt auch gegenüber Admin in der Anwendung; Dateizugriff auf dem Host bleibt technisch möglich (forge §Nutzer)
- (assumption) Ablage auf lokalem Dateisystem /storage; MinIO/S3 aus draft §14 erst mit Zukunftserweiterung S3-native
- (question) Datenquelle Reverse-Geocoding (Nominatim/GeoNames/Natural Earth + Verwaltungsgrenzen) und uneinheitliche Ebene Region; R17 wartet; Weg: bmad-deep-recon
- (question) Zielhardware unbekannt; Import-Durchsatz und Leistungsziele müssen dagegen validiert werden
- (question) Datei-Zeitstempel als Fallback unzuverlässig; Kennzeichnung Zeit unsicher?
- (question) wird der mitgegebene Upload-Pfad auch als Album angelegt?
- (question) Löschen: Original physisch entfernen (inkl. Backups) oder nur logisch; wer darf löschen?
- (question) Datenschutz/DSGVO der öffentlichen Galerie (erkennbare Personen, Einwilligung, Löschwunsch) - Quellen schweigen
- (question) wer setzt Sichtbarkeit Gruppen/public auf fremden Alben/Bildern - nur Owner oder auch Editor/Admin?
- (question) Copyright-Wert in Ableitungen: aus welchem Feld, mit welchem Fallback?
